Engineering / Technical overview

一套规范，
连接整个开发流程。

my-code-style 项目技术全景：从配置分层到脚手架生成，从本地格式化到提交与版本管理。面向接入开发者与后续维护者的源码阅读指南。

v1.4.0 Node.js ≥18（包声明） ESLint · Prettier · Stylelint 2026 / 09 / 18

01 项目概览

把分散在各个工程中的代码检查、格式化、提交约定与版本管理，收敛成一套可复用的 npm 配置。

配置即产品

通过子路径导出配置对象或数组，业务工程使用 require / import 接入。

脚手架落地

my-code-style-init 检测目标工程，并写入配置、Git hooks 与 npm scripts。

分层适配

基础 JS/TS → Vue 3 → uni-app；样式支持 SCSS 与 Less。

这不是前端页面或后端服务：没有业务路由、数据库、应用启动入口或构建产物。主要交付物是 src/ 中的配置和 bin/init CLI。

属性 仓库声明
包名 / 版本 my-code-style / 1.4.0
模块制式 包级 CommonJS；传统配置用 .cjs，Flat Config 用 .mjs
运行环境 engines.node ≥18；实际工具链最低版本仍需检查各依赖 engines
依赖策略 32 个 peerDependencies 均标记 optional；devDependencies 仅 standard-version
发布范围 files 白名单：src、bin、README.md、CHANGELOG.md（npm 另有默认包含文件）
许可证 MIT，仓库含 LICENSE 文件

02 使用价值与收益

接入前，代码格式、检查标准、提交信息与版本号是每个人的个人习惯；接入后，它们成为仓库自身的属性——写进配置文件，并由 Git hooks 在提交那一刻执行。

01 / 使用后的优点

维度 接入前 接入后
代码格式 各自编辑器配置，评审里混入空格/引号/换行差异 全仓库统一：4 空格、无分号、双引号、行宽 100
检查入口 各人自己敲命令，标准不一 pnpm lint / pnpm lint:fix ，规则来自共享配置
提交闸门 靠自觉，问题留到评审或 CI pre-commit 自动修复暂存文件，修不好的直接挡下提交
提交信息 自由文本，历史无法机器解析 conventional commits 强校验， pnpm cz 交互式引导
版本与日志 手工改版本号、手工写 CHANGELOG pnpm release 依 commit 类型自动递增并生成 CHANGELOG
样式代码 基本无人检查（多数项目缺 stylelint） 覆盖 SCSS / Less / Vue 内嵌样式，放行小程序单位与选择器
编辑器与系统差异 换行符、缩进、编码各自为政 .editorconfig + .gitattributes 钉死 EOL 与二进制标记
规则升级 每个项目各抄一份配置，改一处要改 N 处 升级一个依赖版本，全项目规则同步
依赖版本对不上 pnpm 只打一行 WARN 就装完（npm 直接 ERESOLVE 拒装）， “装上了、跑起来才坏”长期潜伏 init 主动体检：已装版本是否落在声明范围内（精确到 minor）、上游配置自己的 peer 是否满足、typescript-eslint 与 @typescript-eslint/parser 是否同版本， 并给出可复制的对齐命令
新人上手 靠口头传达“我们项目这么写” 规则即文档，提交时当场纠错

02 / 带来的福利与解决的问题

过去的问题 接入后
格式争论与评审噪音 格式交给工具，评审只谈逻辑
“我这边好好的”——本地过、CI 挂 同一套规则、同一份配置，结果可复现
提交信息杂乱（update / fix bug / 修改） commitlint 拦截不规范信息，header 上限 108 字符
CHANGELOG 靠人写，常漏常错 standard-version 按 feat / fix / perf 自动生成
提交时不知道该填什么 scope 自动列出源码目录，并按暂存文件猜测当前模块
老项目停在 ESLint 8，新项目用 9，配置分裂 同一份包同时支持 .eslintrc.cjs（v8）与 Flat Config（v9）
新项目每次从零拼装 lint / hooks / 提交规范 init 一次生成 11 个文件 + 6 个脚本，可 --dry-run 预览、--backup 留档
配置写错长期潜伏（如 quotes 与 Prettier 打架） 173 项自动化回归覆盖，含 ESLint 8 / 9 / 10 与 Stylelint 16 / 17 的真实运行
团队规范写在文档里，没人看 hook 在提交那一刻执行，默认路径就是正确路径
装完一片 unmet peer 警告，不知道哪些要管 区分“声明没跟上”与“版本真的对不上”，后者直接在 init 输出里列出对齐命令；支持的 stylelint 16 / 17 两条线都有真实运行回归

03 / 代价与边界

初始化约 300 ms

可 --dry-run 预览、--backup 留档；写入异常自动回滚。

每次提交约 +2.6 s

实测 2 个文件；文件越多越久，空提交约 6 ms。

依赖体积膨胀

devDependencies 增至 27 项，pnpm 虚拟 store 约 512 个包 / 132 MB（硬链接）。

需要接受既有意见

4 空格、无分号、双引号、行宽 100、conventional commits。

hooks 是 软约束 ： git commit --no-verify 可绕过，CI 仍需自行执行 pnpm lint 兜底。本工具不做类型检查（typescript-eslint 为语法级）、不跑测试、不碰业务代码、不代装 peer。

04 / 适合谁

收益最大的是多人 / 多仓库团队、长期维护项目、Vue 3 与 uni-app 工程，以及需要统一 CHANGELOG 的库；单人一次性脚本、已有成熟自建规范且不愿更换的大团队，则应权衡依赖体积与提交耗时。完整评估与 使用步骤见仓库 docs/manual.md 。

04 配置架构

目标项目
package.json / 已有配置 → bin/init
检测 · 生成 · 依赖提示 → 本地配置
引用 my-code-style 子入口 → 工具执行
lint / format / commit / release

ESLint 双轨、三层继承

层级 传统配置（对象） Flat Config（数组）
基础 base.cjs：TS parser、recommended、import、Prettier base.mjs：typescript-eslint、import-x、globals、Prettier
Vue 3 展开 base，设置 Vue parser、Vue essential 与业务覆写 展开 baseConfig，追加 flat/essential 与 .vue 文件规则
uni-app 展开 vue3，加入 uni、wx、Page、App 等 globals 展开 vue3Config，向 vue/ts/js/nvue 文件追加 globals

传统配置用对象展开与 extends 组合；Flat Config 依靠数组次序叠加。 _shared.mjs 集中维护通用规则、Prettier 规则与 uni-app globals，但传统配置仍有单独的规则副本。

两套配置不完全等价：传统版启用 import/extensions，Flat 版关闭 import-x/extensions。Flat 基础数组末尾的 Prettier 推荐配置及 eslint-config-prettier 会覆盖前面部分同名规则，最终行为应以 ESLint 计算后的配置为准。

依据：src/eslint/base.cjs、vue3.cjs、uniapp.cjs 与 src/eslint/flat/*.mjs。

06 初始化机制

检测项 实际决策
项目类型 合并 dependencies / devDependencies / peerDependencies；uni-app 优先，其次 vue，否则 base。
ESLint 版本 读取依赖字符串中的首个数字，并非解析已安装版本或完整 semver 范围。
配置格式 检测为 ESLint 8，或仅有传统配置且无 Flat 配置 → 传统格式；其余 → Flat。
样式类型 只有 Less → less；存在 Sass → scss（两者并存也选 scss）。否则检查已有 .stylelintrc.cjs/js 中的 postcss-less。
样式兜底 Vue/uni-app 默认 scss；普通项目没有相关依赖/配置则 none；缺失或无法读取 package.json 时检测函数默认 scss。

写入什么？

生成选定的 ESLint 配置、Prettier 配置和忽略文件、可选 Stylelint 配置、Commitlint、versionrc、EditorConfig、gitattributes 以及两个 Husky hooks。 .gitignore 仅在不存在时生成；hook 文件会设置为可执行。

初始化不是安全合并器。 多数配置与已有 hooks 会直接覆盖；package.json 的 scripts 保留同名旧值，但 lint-staged 整块替换。Flat 模式始终写 eslint.config.mjs，并不会删除已有 eslint.config.js / ts / cjs，迁移时可能留下多个配置文件。

CLI 参数

npx my-code-style-init --dry-run  # 只展示配置 / hook 创建或覆盖计划
npx my-code-style-init            # 实际写入并提示缺少的依赖
npx my-code-style-init --version  # 或 -v，输出包版本

--dry-run 在写入前返回，也不会执行后面的 package.json 更新和缺失依赖提示。CLI 不自动安装依赖、不执行 husky 初始化，也没有实现交互确认、回滚或 --help 分支；不要把未知参数当作安全的只读操作。

依据：bin/init 的 detection helpers、main、modifyPackageJson、checkPeerDeps。

07 规则与约定

模块 核心约定 / 边界
Prettier 双引号、4 空格、无分号、行宽 100、尾逗号 all、LF；JSON/JSON5 为 2 空格且无尾逗号，YAML 为 2 空格，.nvue 开启分号。
ESLint 缩进交给 Prettier；要求控制语句花括号；允许 any、console、@ts-ignore、空对象类型；关闭多项未使用变量/表达式与 no-undef 检查。它不是严格类型检查的替代品。
Vue 禁用组件多单词命名要求；no-mutating-props 使用 shallowOnly: true；关闭多项模板排版规则。
Stylelint 默认预设面向 SCSS/Vue；Less 有独立预设和覆写片段。支持 rpx、page、deep/v-deep 等；放宽未知函数、空块、选择器特异性等规则。
忽略范围 Flat ESLint 与 Stylelint 内置忽略 node_modules、dist、coverage、public、assets/iconfont 和部分压缩文件；传统 ESLint 基础配置没有同样的 ignores。
Editor / Git src 中的模板统一编辑器与 Git 文本处理；实际项目仍需检查已有忽略规则是否适合自身目录。

Less-only 项目优先用 my-code-style/stylelint/less ，不要把默认 SCSS 预设当作完全等价的 Less 配置。 less-override 只是片段，合并时要同时保留原有 overrides 数组与 rules 对象。

依据：src/prettier/index.cjs、src/stylelint/*.cjs、src/eslint/flat/_shared.mjs。

08 提交与版本流程

git commit → pre-commit
lint-staged 修复暂存文件 → commit-msg
commitlint 验证提交信息 
# .husky/pre-commit
# husky 已把 node_modules/.bin 放进 PATH，优先直连本地 lint-staged
if command -v lint-staged >/dev/null 2>&1; then
    exec lint-staged
fi
npx --no-install -- lint-staged

# .husky/commit-msg
if command -v commitlint >/dev/null 2>&1; then
    exec commitlint --edit "$1"
fi
npx --no-install commitlint --edit "$1"

# 提交信息示例
feat(component): 添加按钮加载状态

lint-staged

采用互斥文件组按序串行执行：Vue/nvue 文件组、脚本文件组、独立样式文件组与配置/文档文件组严格隔离，避免多任务并发写入竞争，并支持 nvue 文件与组件内嵌样式的完整检查与修复。

Commitlint 与 scope

继承 conventional 规则；标题上限 108，subject/type 不可为空，放开 subject-case。支持 feat、fix、perf、style、docs、test、refactor、build、ci、chore、revert、wip、workflow、types、release。

  • generateScopes("src") ：扫描直属子目录、转为单数、去重；也接收多个目录名。
  • guessCurrentScope() ：仅依据 Git 暂存区（staged），按暂存文件所属目录频次投票确定（平票按首个记录，未暂存改动不参与）；支持重命名、删除、多目录、中文与空格路径。
  • 生成器把 scopes/defaultScope 放入 prompt，额外加入 mock；这不是 scope-enum 强制校验。

版本管理边界

pnpm release 运行 standard-version：递增版本、生成 CHANGELOG、创建提交与标签（四个 skip 均为 false）。versionrc 显式配置 feat / fix 的中英文章节。它不会自动把包发布到 npm，也不会自动推送远端；发布权限与 CI 流程需另行建立。

依据：bin/init、src/commitlint/*.cjs、src/versionrc/index.cjs、package.json。

09 接入与日常使用

01 / 在目标项目中初始化

完整步骤、收益评估与常见问题见 docs/manual.md 与 docs/init-flow.md 。 先保存已有配置，并确保目标项目有有效 package.json 与 Git 仓库。以下命令用于消费本包的工程，不建议对本仓库直接执行 init 来“安装依赖”。 

pnpm add -D my-code-style
npx my-code-style-init --dry-run
# 确认覆盖范围后再执行
npx my-code-style-init
# 执行 CLI 输出的、按当前技术栈生成的完整缺失依赖安装命令
pnpm prepare
pnpm lint
optional peers 不代表无需依赖。只安装 my-code-style 不足以保证 lint / hooks 可执行；需要安装所选配置实际引用的工具、插件、解析器与预设。Node ≥18 也只是本包声明，推荐先核验所选依赖的 Node 要求。

02 / 手动接入 Flat Config

// eslint.config.mjs（Vue 3 示例）
import vue3Config from "my-code-style/eslint/flat/vue3"

export default [
    ...vue3Config,
    {
        files: ["**/*.{js,ts,vue}"],
        rules: { "no-console": "warn" },
    },
]

纯 JS/TS 换成 my-code-style/eslint/flat ；uni-app 换成 my-code-style/eslint/flat/uniapp 。自定义规则放在数组后面。传统配置使用 require 并合并 rules，避免直接修改共享对象。

03 / 常用脚本

命令 作用
pnpm lint 检查代码：eslint .
pnpm lint:fix 检查并自动修复
pnpm format Prettier 重写项目文件，执行前确认忽略范围
pnpm cz 使用 czg 交互生成提交
pnpm release 生成版本、日志、提交与标签；不是 npm publish
pnpm pack 本仓库打包：npm pack

CLI 不添加独立的 stylelint script；如需全量样式检查，可在目标工程补充 stylelint "**/*.{vue,css,scss}" （Less 工程替换扩展名）。
